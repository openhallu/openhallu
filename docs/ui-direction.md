# OpenHallu UI Direction

## Design Goal

OpenHallu should feel like a research-native community library, not a generic corporate dashboard.

The visual direction should combine:
- editorial clarity
- modular discovery
- strong card-based browsing
- credible academic tone

## Figma Community-Inspired Traits

We are using Figma Community and Figma skills browsing as inspiration for interaction patterns, not to copy the visual language literally.

What to borrow:
- discovery-first browsing
- clear category grouping
- modular resource cards
- strong entry-point hierarchy
- easy jump from preview surface to source resource

What not to copy blindly:
- generic creator-marketplace styling
- overly soft SaaS gradients
- plugin-market clutter

## OpenHallu Visual Personality

Recommended tone:
- bright, clean, research-forward
- structured but not sterile
- confident and slightly experimental

Recommended visual ingredients:
- strong typography contrast
- dense but readable information cards
- restrained accent colors per module
- subtle diagrammatic or grid backgrounds

## Module Color Logic

Suggested direction:
- Papers: neutral ink / slate
- Benchmarks: cobalt
- Detection: amber or rust
- Mitigation: green or teal

This gives each module its own presence without fragmenting the brand.

## Home Page Layout Direction

### Hero

- one clear statement of what OpenHallu is
- one short supporting sentence
- one call to explore mitigation
- one secondary call to browse all papers

### Discovery strip

- 4 large module cards
- each card includes short description and count placeholder

### Featured content

- featured mitigation papers
- featured toolbox cards
- recent updates

## Mitigation Page Layout Direction

### Section 1

Mitigation intro banner with:
- short definition
- why it matters
- quick links to papers and toolbox

### Section 2

Category pills or segmented explorer

### Section 3

Featured mitigation cards

### Section 4

All mitigation papers in a browsable grid/list hybrid

### Section 5

Toolbox cards with GitHub-first CTA

## Card Behavior

Each card should answer:
- what is this
- why should I care
- where do I go next

For paper cards:
- title
- short one-line summary
- method tags
- source and year
- links

For toolbox cards:
- name
- what it implements
- supported method family
- GitHub CTA

## MVP UI Priority

For the first build, prioritize:
- homepage polish
- mitigation page quality
- card system
- responsive navigation

Do not spend early cycles on:
- animations everywhere
- complicated dashboards
- account flows
- backend-heavy interactions
